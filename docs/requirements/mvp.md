# MVP要件定義（交通費管理）

## ユーザーストーリー

### 1. 月次一覧を見る
**ストーリー**
経費担当者として、対象月の交通費明細を一覧で確認したい。これにより月次の申請・確認作業を効率化できる。

**受け入れ条件（Given / When / Then）**
1. **Given** 2026年03月が選択されている、**When** 月次一覧を表示する、**Then** 2026年03月に属する明細のみが表示される。
2. **Given** 明細データが0件の月、**When** 一覧を表示する、**Then** 「該当データなし」の空状態メッセージが表示される。
3. **Given** 前月・翌月の移動ボタンが表示されている、**When** 前月または翌月へ移動する、**Then** 選択月が更新され対象月データのみ再表示される。
4. **Given** 明細が複数件存在する、**When** 一覧を表示する、**Then** 日付・訪問先・支払先・金額・メモが行単位で視認できる。

### 2. 検索する
**ストーリー**
経費担当者として、明細を素早く絞り込むためにキーワード検索したい。

**受け入れ条件（Given / When / Then）**
1. **Given** 検索欄が表示されている、**When** キーワードを入力する、**Then** 訪問先に一致する明細が表示される。
2. **Given** 検索欄が表示されている、**When** キーワードを入力する、**Then** 支払先に一致する明細が表示される。
3. **Given** 検索欄が表示されている、**When** キーワードを入力する、**Then** メモに一致する明細が表示される。
4. **Given** 複数項目に一致する明細がある、**When** 検索する、**Then** 重複なく1行として表示される。
5. **Given** 検索キーワードをクリアした、**When** 検索状態を解除する、**Then** 対象月の全件表示に戻る。

### 3. 明細を編集/削除する
**ストーリー**
経費担当者として、誤登録を修正したり不要な明細を削除したい。

**受け入れ条件（Given / When / Then）**
1. **Given** 一覧上に既存明細がある、**When** 編集操作を行う、**Then** 当該明細の入力済み値がフォームに表示される。
2. **Given** 編集フォームで必須項目を更新した、**When** 保存する、**Then** 一覧に更新内容が即時反映される。
3. **Given** 削除対象の明細がある、**When** 削除操作を開始する、**Then** 確認ダイアログが表示される。
4. **Given** 確認ダイアログで削除を確定した、**When** 削除処理が完了する、**Then** 一覧から当該明細が除外される。
5. **Given** 確認ダイアログでキャンセルした、**When** 削除処理を中断する、**Then** 明細は削除されず一覧状態が維持される。

### 4. 交通費を登録する
**ストーリー**
経費担当者として、新しい交通費明細を登録したい。

**受け入れ条件（Given / When / Then）**
1. **Given** 新規登録フォームが表示されている、**When** 日付・訪問先・支払先・金額を入力する、**Then** 保存可能状態になる。
2. **Given** 必須項目が不足している、**When** 保存を試みる、**Then** 項目単位のエラー表示が出て保存されない。
3. **Given** 入力値が妥当である、**When** 保存する、**Then** 新規明細が対象月一覧に追加される。
4. **Given** 金額に不正値（負数・文字列）が入力された、**When** 保存する、**Then** バリデーションエラーを表示する。

### 5. 履歴から再利用する
**ストーリー**
経費担当者として、過去の利用履歴をコピーして入力の手間を減らしたい。

**受け入れ条件（Given / When / Then）**
1. **Given** 履歴一覧に過去明細が存在する、**When** 任意の履歴を選択する、**Then** 訪問先・支払先・金額・メモが入力フォームに反映される。
2. **Given** 履歴を再利用して日付のみ変更した、**When** 保存する、**Then** 新規明細として登録され元履歴は変更されない。
3. **Given** 履歴が存在しない、**When** 再利用画面を表示する、**Then** 「再利用可能な履歴なし」と表示される。
4. **Given** 再利用時に一部項目を手動修正した、**When** 保存する、**Then** 修正後の値で新規登録される。

### 6. CSV/テキストを出力する
**ストーリー**
経費担当者として、提出や共有のために月次データをCSVまたはテキストで出力したい。

**受け入れ条件（Given / When / Then）**
1. **Given** 対象月の明細が存在する、**When** CSV出力を実行する、**Then** 対象月データのみを含むCSVファイルが生成される。
2. **Given** 対象月の明細が存在する、**When** テキスト出力を実行する、**Then** 日付・訪問先・支払先・金額・メモを含む整形テキストが生成される。
3. **Given** 検索フィルターが適用されている、**When** 出力する、**Then** 画面表示中の絞り込み結果のみが出力対象となる。
4. **Given** 出力処理が正常終了した、**When** 完了通知を受ける、**Then** 利用者にダウンロード可能であることが明示される。

## 非機能要件

1. **モバイル優先UI**
   - 390px幅を基準としたモバイルファースト設計とする。
   - 主要操作（一覧確認・検索・登録・編集・削除・出力）は片手操作を考慮した配置とする。

2. **初回描画性能**
   - 主要画面（対象月一覧）の初回描画は3秒以内（通常回線想定）を目標とする。
   - 読み込み中はローディング表示を提供し、操作不能状態を明確化する。

3. **アクセシビリティ**
   - フォーム要素にラベルを関連付ける。
   - キーボード操作のみで主要機能に到達可能とする。
   - エラー時は視覚的表示に加えて支援技術で認識可能なメッセージを提供する。

4. **監査ログ**
   - 登録・編集・削除・出力の操作について、実行日時・操作種別・対象IDを記録する。
   - 監査ログは改ざん検知可能な形式で保持し、必要時に参照できること。

5. **障害時の再試行**
   - 一時的な通信障害時、利用者が明示的に再試行できるUIを提供する。
   - 自動再試行を行う場合は最大回数を定義し、失敗時に利用者へ結果を通知する。

## MVP外（後続フェーズ）

以下は本MVPの対象外とし、後続フェーズで検討する。

- 承認ワークフロー（申請・承認・差戻し）
- 多通貨対応（為替換算・通貨別集計）
- ICカード連携（交通系ICの自動取り込み）
- 会計システムへの自動仕訳連携
- 高度な分析ダッシュボード（部門別/プロジェクト別可視化）
